# Contributing

Discuss changes in
[this repository's Issues](https://github.com/ktanino10/talkvideo-mcp/issues).
Do not open upstream issues/PRs, mention original authors, or assign them
responsibility for this independent implementation.

## Development

Use Python 3.11+ on macOS or Linux and `uv`, from the repository root:

```sh
uv sync --locked --group dev
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src
uv build
```

Local FFmpeg and ffprobe enable the diagnostic video tests. Tests explicitly
skip those cases when the tools are missing. No test calls a speech service,
downloads a model, or loads real-person footage. Native stdio tests use the
installed official SDK, not just direct Python function calls.

## Implementation boundaries

Keep the core local, sequential and inspectable. Use the pinned official MCP
SDK; update the lockfile and protocol tests together when upgrading. Keep
model dependencies separate. Do not add automatic downloads, uploads, default
paid-service activation, global configuration changes, or release publication.
The official API remains operator-opt-in; tests must inject both HTTP transports
and runtime-only fake keys, never documentation sample keys or a live service.
Preserve durable Retry-After deadlines and GET-only recovery after a confirmed POST.

Every advertised capability needs a tested implementation. Unavailable
backends return actionable errors, not fixture media labeled as speech or
lip-sync. Interactive review and media rights are separate from tool input.

Preserve exact Unicode rejoining, stable cue identity, cumulative retry
budgets, content hashes, immutable revisions, and frame-based offsets.
Add failure/interruption tests with any lifecycle changes. Use argument-array
subprocesses with bounded I/O, timeout and process-group cleanup.

Keep stdout protocol-only. Log codes/types, not scripts, credentials,
provider responses, full validation errors or personal paths.

## Public repository hygiene

Do not commit output, media, model weights, user scripts, credentials,
local settings, or agent-evaluation transcripts. Synthetic fixtures are
generated by tests. Keep third-party attribution/licenses if reusing code;
do not imply original code was copied.

An SDK stdio smoke test is not an installed/authorized Copilot host test.
A workflow/routing evaluation is not a speech or perceptual lip-sync test.
Keep those distinctions in PR evidence and documentation.
